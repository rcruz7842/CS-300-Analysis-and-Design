# CS-300: Analysis and Design

# Project Overview

For my CS-300 course, I created a course advising program in C++ using a binary search tree. The program reads course information from a CSV file and allows users to view the courses in order, search for a specific course, and see its prerequisites.

# Technologies and Concepts
- C++
- Binary search trees
- Vectors and hash tables (design comparison)
- Recursion and pointers
- File handling and input validation
- Data structures and algorithms

# Project Reflection
Throughout these projects, I learned how to use different data structures to store and organize information for a student course advising program. I started by comparing vectors, hash tables, and binary search trees to see how each one handled the same tasks. The vector was probably the easiest to work with, but I ended up going with the binary search tree because I wouldn't have to sort the courses separately every time I wanted to print them. I also looked at the runtime and memory usage for each one, which made me realize that just because something works doesn't necessarily mean it's the best way to do it.

Once I got to Project Two, I had to take what I'd planned out and actually write the program in C++. I worked through the functions one at a time since trying to do everything at once would've been a headache. The pointers and recursion took a little more thought, especially making sure the program was moving through the tree correctly. I tested the different functions as I worked on them and went back through my code to check for anything I might've missed. I also added checks for duplicate courses, missing prerequisites, and invalid input instead of assuming the file or user would always give the program the right information.

The biggest takeaway from these projects is that I need to spend more time thinking about how I'm going to build something before I start coding. I've always been the type to jump into figuring things out as I go, but that can make things harder on myself later. Breaking things into smaller functions, keeping my code organized, and adding comments where they actually help makes it easier to go back and work on something without getting lost in my own code. I'm still learning, but I'm getting better at thinking ahead about what might need to be changed or fixed later.
